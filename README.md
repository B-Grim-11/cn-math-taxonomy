# 中国初中数学（七—九年级）知识图谱 · 第一版草稿

用「知识点节点 + 先修边」的有向无环图（DAG）描述人教版初中数学（七上至九下）的知识结构，数据格式参考 [Marble os-taxonomy](https://github.com/withmarbleapp/os-taxonomy)（`topics` + `dependencies`）。

> **状态声明：这是 AI 生成的初稿，未经任何教师审核。**
> 知识点的拆分粒度、掌握标准、诊断题答案，尤其是**先修关系（哪些是 hard、哪些是 soft，甚至某条边该不该存在）都需要一线初中数学教师审核**后才能用于教学、诊断或学习路径推荐。诊断题答案虽经抽查心算，但没有逐题由人工复核。

### topics.json 字段

正式知识点（`external: false`）：

| 字段 | 说明 |
|---|---|
| `id` | 稳定 id，`cnm_001` … |
| `name` | 中文名称 |
| `domain` | 数与代数 / 图形与几何 / 统计与概率 / 综合与实践 |
| `grade` | 7 / 8 / 9（整数） |
| `semester` | "上" 或 "下" |
| `chapter` | 人教版章节，如 `七上 第一章 有理数 1.2.1` |
| `type` | conceptual / procedural / reasoning / application / modeling |
| `description` | 通俗说明（1—2 句） |
| `mastery_criteria` | 2—3 条掌握标准（字符串数组） |
| `diagnostic_question` | `{"question": "...", "answer": "..."}` |
| `external` | `false` |
| `standards` | 课标映射数组，元素 `{"id", "confidence", "note"?}`，见下节；可为空数组 |
| `root_reason` | 仅当非外部节点没有任何先修边时必填（本版没有这样的节点，见下） |

外部（小学先修）节点：只有 `id`、`name`、`domain`、`grade`（固定为 `"小学"`）、`description`、`external: true`，另有 `standards: []`（本版没有做第三学段课标条目）。

说明：
- 数学里函数归“数与代数”，点的坐标、图形变换归“图形与几何”（与课标领域划分一致）。
- “综合与实践”节点（如 `设计学校田径运动会比赛场地`）是教材中的主题活动，按 `modeling` 处理，诊断题只是对活动中某一数学要点的检查。
- `一元二次方程根与系数的关系（拓展）`：课标要求“了解”（例67），第三轮已据此更正描述；名称里的“（拓展）”保留，其是否作为必学请教师判断。

### dependencies.json 字段

```json
{"topicId": "A", "prerequisiteId": "B", "strength": "hard", "reason": "一句中文理由"}
```

含义：**A 依赖 B**（学 A 之前需要 B）。

- `hard`：不会 B 基本无法学 A；`soft`：会 B 对学 A 明显有帮助（类比、简化、背景），但不是硬门槛。**这个区分是 AI 的主观判断，未经审核。**
- 只保留直接先修关系，并做了传递约简：`hard` 边仅在存在另一条全 `hard` 路径时才被删除，`soft` 边在存在任何其他路径时即被删除（生成时共剔除 90 条冗余边）。因此若看到某条边“缺失”，通常是已经能由更近的先修推出。
- 由于每个正式知识点最终都能追溯到至少一个小学外部节点，**本版没有需要 `root_reason` 的根节点**；图的根全部是 `cnm_ext_*`。

## 诊断小工具（第四轮；第五轮改为每个知识点最多 2 题）

`diagnose/` 是一个基于上述数据的静态、可离线的诊断页面：选一个目标知识点（或整个章节），按先修关系自适应出题（第一题答对则掌握并跳过全部祖先；答错则再出一道同级或更容易的题——第二题也错才算薄弱并回溯到先修，hard 先于 soft；第二题答对标为「不稳」，不回溯），给出薄弱的根因、不稳的知识点、按拓扑序排列的学习路径、相关课标条目原文和一张纯 SVG 路径图；每题作答后显示解析和参考答案；进度保存在 localStorage，可导出 JSON 或打印。核心算法与判题在 `diagnose/engine.js`（纯函数，浏览器与 Node 通用），由 `node tests/test_engine.js` 测试。

```bash
python3 -m http.server 8000
# 访问 http://localhost:8000/diagnose/            （演示：?target=cnm_221&demo=1）
node tests/test_engine.js                          # 引擎测试
node scripts/screenshot.js                         # 冒烟测试 + 截图（需要本机 Chrome）
```

算法说明、判题规则、URL 参数与局限见 [diagnose/README.md](diagnose/README.md)；浏览页 `index.html` 右上角也有入口。每个知识点最多问 2 题，诊断结果只是线索。

```bash
python3 scripts/verify_questions.py   # 自动核验，写 data/verification_report.json；mismatch 为 0 才打印 VERIFICATION PASSED
python3 scripts/validate.py           # 含题库格式检查与题量统计
```

题目与答案全部由 AI 生成、未经教师审核，复核者与出题者是同一模型家族；格式、核验方法、统计与局限见 [docs/questions.md](docs/questions.md)。

## 已知局限

- **审核缺位**：见开头状态声明；先修关系、hard/soft 强度、诊断题难度与区分度都没有经过教师或学生数据检验。
- **覆盖不均**：统计与概率现为 43 个，但全部集中在七下、八下、九下三册（新教材只在这三册安排统计与概率，不含七上、八上、九上）；九下目录为第三方来源推定，非官方、待核（见上）；教材中的“阅读与思考”“数学活动”“小结”“信息技术应用”等栏目没有单独成点，仅少数“综合与实践”“探究与发现”并入。
- **粒度不统一**：个别知识点（如各类应用题）按题型归并，个别（如三角形全等的各判定）拆得较细，需按实际教学再调。
- **题库很小**：每个知识点 4–5 题、诊断时最多问 2 题，题与答案由 AI 生成、未经教师审核，难度与干扰项没有学生数据校准，不能代替完整测评。
- **按教材顺序推断**：部分先修边（如命题、定理类内容）反映的是教材编排而非严格逻辑依赖，已尽量标为 `soft`。

## 运行校验

```bash
python3 scripts/validate.py
```

检查：JSON 合法；id 唯一；必填字段齐全；`domain`/`type`/`strength` 取值合法；每条边的两端都存在；无自环、无重复边；无环（有环时打印环路）；每个非外部知识点要么有先修边要么有 `root_reason`；没有完全孤立的节点。并打印按领域、按册次的数量以及边数、hard/soft 数。第三轮新增：`standards` 引用的课标 id 必须存在于 `data/cn-curriculum-standards.json`，`confidence` 只能是 `exact`/`inferred`，课标文件自身的 id 格式与编号连续性；并打印课标条目数、映射覆盖率；正式知识点 `standards` 为空时只打印警告（至多 30 个），设置 `STRICT_STANDARDS=1` 才视为错误。全部通过时输出 `VALIDATION PASSED` 且退出码为 0，否则输出错误并以非 0 退出。

python3 -m http.server 8000

功能：左侧可按学科、年级/册次、类型筛选并搜索（名称、描述、章节）；可勾选是否显示小学先修节点。点击知识点后显示描述、掌握标准、诊断题（答案默认折叠）、**先修链**（向上递归，树状或分层列表两种视图，边上标注硬/软先修及理由），以及**它是哪些后续知识点的先修**。地址栏 `#cnm_219` 形式的 hash 可直接定位到某个知识点。

## 后续建议

1. 请初中数学教师先审先修边（尤其是 hard 边），并用教材实物或人教社官方目录核对九下的章名、章号和小节号。
2. 请课程专家审核 `standards` 映射（尤其 inferred），并考虑为 15 条无对应知识点的课标条款补点；再补充每个知识点的常见错误、典型例题。
3. 用真实学生答题数据校准诊断题与先修强度。
